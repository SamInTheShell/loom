# General knowledge

A general-purpose primer: working methodologies that apply regardless of
specialization - how to plan, sequence, and verify substantial work.
Everything here is written as practice for whoever is doing the work; a
person at a keyboard and a model in a chat follow the same steps.

Specializations live in their own knowledge folders next to this one:
`knowledge/programming/` carries language- and tooling-specific knowledge.

## How to navigate this folder

Knowledge is sorted by methodology into top-level folders. Every folder
has a README listing its contents.

```
README.md            you are here - the map
engineering/         language-agnostic practice
  project-planning.md  milestones, gates, STATUS.md - planning big builds
```

To find something: search for the topic (`knowledge_search` from a chat,
or the Library tab's search box), then read the match. When a README
turns up in the matches, read it first - it says which file in that
folder actually answers the question.

## Adding knowledge

1. Pick a methodology folder (`engineering/`, or add a new top-level one
   such as `writing/` or `operations/`). Specializations - a language, a
   product, a codebase - deserve their own folder under `knowledge/`.
2. Inside it, one folder per subject, one file per topic. Small focused
   files beat big ones - search hits are read file-by-file.
3. Give each file a `# heading` and lead with the recommendation, then
   the explanation. The first screenful may be all that gets read.
4. Write in the unified voice: state what to do and why it works, for
   whoever executes it. No separate instructions per kind of reader.
5. List the new file in the folder's README so it stays discoverable.

This folder is plain files in the library - edit or delete freely in the
Library tab.
